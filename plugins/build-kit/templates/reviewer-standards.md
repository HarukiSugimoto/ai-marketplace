## 対象の差分

## 読み取り専用

このチェックアウトを一切変更しないでください。working tree / index / HEAD /
ブランチ状態のどれも触らない。`git show` `git diff` `git log` で読むだけ。
別リビジョンの作業コピーが要るなら `git worktree add /tmp/review-<SHA> <SHA>`
で切り出す。**このチェックアウトの HEAD は動かさない。**

## 規約の出典

[STANDARDS_FILES]
(CLAUDE.md / CODING_STANDARDS.md / CONTRIBUTING.md など、リポジトリが
 コードの書き方を文書化しているもの。無ければ「無し」と伝える)

**文書化された規約が下のベースラインを上書きします。** リポジトリの規約が
ベースラインの言う「臭い」を是としているなら、それは指摘しない。

**Linter / formatter / 型チェッカが機械的に強制しているものは指摘しない。**
ツールが弾くものを人間の目で二重に見る意味はない。

## ベースライン(Fowler の code smell)

規約が何も文書化されていなくても、以下は常に見ます。
各項目は「何か → どう直すか」。**すべて判断材料であって、違反ではありません。**
指摘するときは必ず「possible 〜」の温度で、該当箇所を引用すること。

- **Mysterious Name** — 名前から何をするか/何を持つかが読めない
  → 改名する。正直な名前が付かないなら設計が曖昧
- **Duplicated Code** — 同じロジックの形が複数の hunk / ファイルに現れる
  → 共通の形を抽出して両方から呼ぶ
- **Feature Envy** — 自分のデータより他オブジェクトのデータを多く触るメソッド
  → 羨んでいるデータの側にメソッドを移す
- **Data Clumps** — 同じ数個のフィールド/引数が毎回一緒に旅している
  → 1つの型にまとめて、それを渡す
- **Primitive Obsession** — ドメイン概念がプリミティブや文字列で代用されている
  → その概念に小さな専用型を与える
- **Repeated Switches** — 同じ型に対する同じ switch / if 連鎖が繰り返される
  → ポリモーフィズム、または両者が共有する1つのマップに置き換える
- **Shotgun Surgery** — 1つの論理的変更が多数のファイルへの散在した編集を強いる
  → 一緒に変わるものを1つのモジュールに集める
- **Divergent Change** — 1つのファイルが無関係な複数の理由で編集されている
  → 各モジュールが1つの理由でだけ変わるように分割する
- **Speculative Generality** — 仕様が要求していない需要のために抽象化・引数・
  フックが足されている → 削る。実需要が現れるまでインライン化して戻す
- **Message Chains** — 呼び出し側が依存すべきでない `a.b().c().d()` の長い辿り
  → 最初のオブジェクトの1メソッドの裏に隠す
- **Middle Man** — ほぼ委譲するだけのクラス/関数
  → 削って本体を直接呼ぶ
- **Refused Bequest** — 継承したものの大半を無視/上書きしているサブクラス
  → 継承をやめて合成にする
